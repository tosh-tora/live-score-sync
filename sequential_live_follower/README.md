# Sequential Live Follower

Real-time orchestral performance tracker that monitors live audio, aligns it with MusicXML notation, and automatically controls PowerPoint slides at specified measures.

## Features

- **Real-Time Audio Analysis**: Captures microphone input and extracts Chroma features
- **DTW-Based Alignment**: Uses PyMatcher to align live performance with score
- **Measure-Accurate Triggers**: Automatically sends keyboard commands at configured measures
- **Robust Fallback**: Maintains playback continuity using tempo extrapolation when confidence is low (inertia mode)
- **Sequential Movement Loading**: Press 'N' key to load next movement from config
- **Live Display GUI**: Shows current measure, confidence, and next trigger in large, visible format

## System Architecture

### Threading Model

```
Main Thread (tkinter GUI)
├─ FollowerGUI (real-time display)
└─ Worker Threads (background):
   ├─ AudioCapturer (PyAudio stream → audio_queue)
   ├─ FeatureExtractor (audio_queue → Chroma features → feature_queue)
   ├─ MatchingEngine (feature_queue → DTW matching → beat/measure updates)
   ├─ TriggerExecutor (trigger evaluation → pyautogui actions)
   └─ KeyboardListener (global 'N' key handler)
```

### Core Components

| Module | Purpose |
|--------|---------|
| `score_mapper.py` | Beat ↔ Measure conversion with variable time signature support |
| `audio_capturer.py` | Real-time microphone capture via PyAudio |
| `feature_extractor.py` | Chroma feature extraction using librosa |
| `matcher.py` | PyMatcher DTW integration for beat tracking |
| `state_manager.py` | Thread-safe central state store |
| `inertia_engine.py` | Confidence-based beat extrapolation fallback |
| `cooldown_timer.py` | Trigger rate limiting (prevent misfires) |
| `gui_tkinter.py` | Tkinter GUI for live display |
| `config/loader.py` | JSON configuration file parser |
| `main.py` | Application orchestrator |

## Configuration

Create `config.json` (template: `config_example.json`):

```json
{
  "settings": {
    "cooldown_seconds": 3.0,
    "confidence_threshold": 0.4
  },
  "movements": [
    {
      "id": 1,
      "xml_file": "guide_mv1.xml",
      "triggers": [
        { "measure": 1, "action": "right", "note": "Start" },
        { "measure": 45, "action": "right", "note": "Theme A" }
      ]
    }
  ]
}
```

### Configuration Fields

- **cooldown_seconds** (float): Grace period after trigger fires (prevents rapid re-triggering)
- **confidence_threshold** (float): Below this, inertia mode activates (tempo extrapolation)
- **xml_file** (str): MusicXML guide score (from `compressor.py`)
- **triggers** (list): Measure numbers and corresponding keyboard actions
- **action** (str): Keyboard key ('right', 'left', 'up', 'down', 'space', etc.)

## Usage

```bash
# Start the application
python -m sequential_live_follower.main config.json

# With verbose logging
python -m sequential_live_follower.main config.json -v
```

### Workflow

1. **Application Start**: GUI opens, waiting for first movement
2. **Press 'N'**: Loads first movement from config, starts audio capture
3. **Perform**: Begin playing or singing into microphone
4. **Auto-Sync**: Application automatically syncs to current measure
5. **Triggers Fire**: At configured measures, keyboard commands are sent (e.g., 'right' for next slide)
6. **Next Movement**: Press 'N' again to load next movement
7. **Exit**: Close GUI window or press Ctrl+C

### Display

The GUI shows:
- **File Name**: Current MusicXML file
- **Large Measure**: Current measure (1-indexed)
- **Confidence Bar**: DTW alignment quality (green = high, red = low)
- **Next Trigger**: Upcoming measure with trigger
- **[INERTIA MODE]**: Indicates confidence below threshold (using tempo extrapolation)
- **Cooldown Indicator**: Shown when trigger is in grace period

## How It Works

### Beat Tracking (Real-Time Flow)

1. **Audio Capture**: AudioCapturer reads microphone → audio_queue (44.1kHz, float32)
2. **Feature Extraction**: FeatureExtractor buffers frames, extracts 12-D Chroma via librosa → feature_queue (~86 Hz output)
3. **Matching**: MatchingEngine runs PyMatcher DTW on each Chroma vector → (beat, confidence)
4. **Inertia Fallback**: If confidence < threshold, extrapolate beat using last known tempo
5. **Measure Conversion**: ScoreMapper converts beat to measure number using beat↔measure map
6. **State Update**: AppState updated with (beat, measure, confidence, inertia_mode)
7. **GUI Display**: GUI polls state every 100ms, updates display
8. **Trigger Check**: TriggerExecutor checks if current measure has trigger, respects cooldown
9. **Action Execute**: PyAutoGUI sends keyboard command (e.g., 'right')

### ScoreMapper (Critical Component)

Handles variable time signatures by building a cumulative beat map during initialization:

```
Measure 1 (4/4): beats 0.0–4.0
Measure 2 (3/4): beats 4.0–7.0
Measure 3 (5/8): beats 7.0–9.25
...
```

Binary search provides O(log n) beat→measure lookup.

### Inertia Mode

When confidence drops below threshold (default 0.4):
- Last high-confidence beat is recorded
- Current tempo estimated from beat jump rate
- Playback advances using: `new_beat = last_beat + (tempo_bpm / 60) × time_delta`
- Maintains smooth playback during difficult passages (silence, low SNR, etc.)

## Troubleshooting

### Audio Capture Issues

- **No audio input**: Check microphone is selected in system audio settings
- **Crackling/dropout**: Reduce chunk_size or feature_queue size
- **High latency**: Feature extraction lag is expected (~100ms); increase chroma_hop_length

### Matching Problems

- **Constant "INERTIA MODE"**: Confidence always low → audio quality poor or score mismatch
- **Jumps between measures**: Beat reset possible → check for large tempo changes in score
- **Triggers not firing**: Verify config.json measure numbers match actual score measures

### Keyboard Input

- **'N' key not working**: Install `keyboard` library or use alternative input method
- **Slides not advancing**: Verify PowerPoint is in focus and accepts keyboard commands

## Performance Notes

- **CPU Usage**: Feature extraction (librosa) is most expensive; consider reducing chroma_hop_length if CPU-constrained
- **Latency**: Total end-to-end latency ~200-400ms (audio capture + feature extraction + matching + GUI)
- **Memory**: Moderate; queue sizes capped to prevent unbounded growth

## API Overview

### Starting a Session

```python
from sequential_live_follower.main import SequentialFollower

app = SequentialFollower("config.json")
app.run()  # Blocks until GUI closes
```

### Programmatic Access (Advanced)

```python
from sequential_live_follower.core.score_mapper import ScoreMapper
from sequential_live_follower.core.inertia_engine import InertiaEngine

# Convert beat to measure
mapper = ScoreMapper("guide_mv1.xml")
measure = mapper.beat_to_measure(45.5)

# Estimate beat with inertia
inertia = InertiaEngine(confidence_threshold=0.4)
beat, is_inertia, tempo = inertia.update(current_beat=45.0, confidence=0.3)
```
