# 汎用オーケストラ追従スライド制御システムの構築

仕様書は specification.txt にあります。

以下の仕様に基づき、2つのPythonプログラムを実装してください。

## Task 1: Algorithmic MusicXML Compressor (Standalone)
`music21` を使用し、フルスコアから「pymatchmakerが認識しやすい骨格」を自動抽出するスクリプトを作成してください。
1. 特定の楽器名に依存せず、各小節において pymatchmaker が認識しやすいパートを動的に特定すること。
 - 「垂直方向の重複」の回避: 同じタイミングで全員が同じ音を弾いている場合（ユニゾン）、それは1つの情報として扱います。
 - 「リズムの解像度」: 8分音符しかないパートよりも、16分音符が含まれるパートの方が、「時間の経過」をより細かく認識できます。
2. 各小節で上位3〜5パートを選び、それらを1つのトラックに統合（Flatten）すること。
3. 結果を新たなMusicXMLファイルとして保存すること。
4. 処理前に、元ファイルに含まれる全パート名とIDを一覧表示すること。

## Task 2: Sequential Live Follower (Main Application)
`pymatchmaker`, `partitura`, `pyaudio`, `pyautogui` を使用したメインアプリを作成してください。

1. **初期化とロード:**
   - キーボードの 'N' キーを押すたびに、`config.json` に定義された次の楽章（MusicXMLとトリガー設定）を順次読み込むこと。
   - `partitura` を使い、読み込んだXMLから「累積拍数から小節番号への変換マップ」を自動構築すること（変拍子対応）。

2. **リアルタイム追従:**
   - マイク入力をChroma特徴量に変換し、`Matchmaker` で現在の拍数を特定。
   - 特定された拍数を小節番号に変換し、`config.json` の `measure` 到達時に `pyautogui.press('right')`（または指定のアクション）を実行。

3. **ロバスト性と表示:**
   - 信頼度（Confidence）が低い間は、直前のテンポを維持して仮想的に進む「慣性モード」を実装すること。
   - 1回トリガーを引いたら3秒間は再発火を防止（クールダウン）。
   - コンソールまたはtkinter等のGUIで「現在のファイル名、小節番号、信頼度、次のトリガー小節」を大きく表示すること。

確認点や改善点があれば教えてください。

Task 1の「小節ごとの活動量に基づいた自動パート抽出・統合ロジック」のプロトタイプから作成したいです。
